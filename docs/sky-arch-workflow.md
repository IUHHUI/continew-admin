## 逻辑
### 卡密
1. 用户下单后, 运营登录后台, 创建卡密, 自动创建任务和登录游戏的连接给用户.

### 用户登录游戏
1. 用户打开登录游戏的连接, 会打开用户登录游戏页面
2. 选择渠道,输入登录信息, 点击登录
3. 后台接到登录任务, 放入redis队列
4. 云手机轮询请求任务队列, 获取登录信息
5. 云手机执行登录脚本, 返回结果

### 云手机执行登录任务
1. 云手机状态空虚,接到密码登录任务后, 执行.状态转执行中, 执行成功, 上报执行成功. 执行失败,上报执行失败.
2. 云手机状态运行中, 不处理任何任务 .
3. 云手机状态失败, 如果任务数据没有更新, 不继续处理. 如果更新,继续处理.
4. 云手机状态成功, 如果是两阶段登录任务, 等待下一个阶段 目前只有二维吗和验证码. 如果是阶段2成功, 标记任务成功, redis 移除卡密. 
   - 二维码等待自动来到阶段2. 
   - 验证码, 下发二阶段的任务.

### 云手机
1. 新设备,增加设备信息到mysql
2. 设备根据类型获取登录任务或者游戏任务
3. 默认是游戏任务类型云手机, 变更类型, 需要运营手动在后台更新云手机的类型.

## redis
``` shell
docker run --name my-redis 
-v /path/to/your/redis.conf:/usr/local/etc/redis/redis.conf 
-d redis redis-server /usr/local/etc/redis/redis.conf
```
